# Codex Usage Widget v1.1.0

## English

Version 1.1.0 brings the same compact usage-ring experience to Windows and macOS. Both apps use the shared local-session contract, the same five language packs, eight theme identities, 180 ms hover behavior, active-task rules, and cumulative cache-token rules.

### Downloads

| Platform | Recommended | Checksum | Alternative |
|---|---|---|---|
| Windows | `CodexUsageWidget-v1.1.0-windows.exe` | `.exe.sha256` | `CodexUsageWidget-v1.1.0-windows.zip` and `.zip.sha256` |
| macOS | `CodexUsageWidget-v1.1.0-macos.dmg` | `.dmg.sha256` | Build the same tagged source locally |

The Windows EXE is not yet Authenticode-signed; verify its checksum. The public macOS DMG must be signed with a Developer ID Application certificate, notarized, and accepted by Gatekeeper. The maintainer needs the Developer ID; users do not.

GitHub source archives are generated from the same `v1.1.0` tag. One version number covers both platforms because it identifies the feature set.

### What changed

- Added the native macOS 13+ app with Universal `arm64` and `x86_64` support.
- Added the single-file Windows EXE while keeping the portable ZIP and hidden VBS launcher.
- Added isolated `-Demo` and `--demo` modes backed by fictional contract data.
- Added bounded scan workers and cross-platform contract, data-boundary, UI, package, and CI checks.
- Kept local discovery order consistent: saved path, `CODEX_HOME`, home `.codex`, then folder picker.

### Privacy and state

Neither app calls Web APIs, uploads session data, or stores Codex credentials. Windows state is under `%LOCALAPPDATA%\CodexUsageWidget`; macOS state is under `~/Library/Application Support/CodexUsageWidget`. Each stores preferences, `cache-token-ledger.json`, and `reminders.json`. A manually chosen network path uses normal operating-system file access.

### Upgrade and rollback

Exit v1.0.0 before installing v1.1.0. Windows users can retain the previous extracted directory; macOS users can retain the previous app bundle. The state format remains compatible. To roll back, exit v1.1.0 and start the retained version. Always verify the downloaded checksum first.

### Known limits

- Values are best-effort observations of local session files, not official account, billing, or entitlement data.
- The Windows EXE has no Authenticode signature in this release.
- Public macOS distribution cannot proceed without the maintainer's Developer ID signing and Apple notarization evidence.

### 本次更新

- 新增原生 macOS 13+ 应用，同时支持 `arm64` 和 `x86_64`。
- 新增单文件 Windows EXE，并保留便携 ZIP 和隐藏启动的 VBS。
- 新增隔离的 `-Demo` 与 `--demo` 演示模式，只使用虚构契约数据。
- 新增有边界的扫描进程，以及跨平台契约、数据边界、界面、打包和 CI 检查。
- 两端保持同一数据定位顺序：已保存路径、`CODEX_HOME`、用户 `.codex`，最后手动选择。

### 隐私与本机状态

两个应用都不调用 Web API，不上传会话数据，也不保存 Codex 凭据。Windows 状态位于 `%LOCALAPPDATA%\CodexUsageWidget`，macOS 状态位于 `~/Library/Application Support/CodexUsageWidget`，其中包含偏好、`cache-token-ledger.json` 和 `reminders.json`。手动选择网络路径时，会发生操作系统正常的文件访问。

### 更新与回退

安装 v1.1.0 前先退出 v1.0.0。Windows 可保留旧解压目录，macOS 可保留旧应用副本。状态格式保持兼容；需要回退时退出 v1.1.0，再启动保留的版本。下载后请先核对校验值。

### 已知限制

- 所有数值都来自本机会话文件的尽力观测，不是官方账户、账单或权益数据。
- 本版 Windows EXE 没有 Authenticode 签名。
- 维护者取得 Developer ID 并完成苹果公证验证前，不能发布 macOS 公共安装包。
