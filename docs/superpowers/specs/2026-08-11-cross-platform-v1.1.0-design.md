# Codex Usage Widget v1.1.0 跨平台发布设计

日期：2026-08-11

状态：已批准，等待实施计划

## 目标

v1.1.0 在保持现有统计语义与桌面体验的前提下，同时提供：

- Windows 单文件免安装 EXE；
- 现有 Windows ZIP；
- macOS 13 及以上可运行的原生通用应用，覆盖 Apple 芯片与 Intel；
- 同一个 GitHub 标签、Release、源码版本和变更记录；
- 每个二进制资产对应的 SHA-256 校验文件。

两个平台继续只读取用户指定或自动发现的本机 Codex 会话文件，不调用 Web API，不上传数据，也不保存账号凭据。

## 非目标

- 不重写已经稳定的 Windows PowerShell/WPF 主程序。
- 不为共享代码引入 Electron、Tauri、Avalonia 或其他跨平台运行时。
- 不发布依赖 PowerShell 的 macOS 包。
- 不在没有 Apple Developer ID 签名和公证的情况下公开发布 v1.1.0 macOS 正式资产。
- 不在 v1.1.0 中加入自动更新、安装器服务、账号系统或云同步。

## 版本与发布原则

Windows 和 macOS 使用同一个功能版本号。新增 Windows EXE 和 macOS 支持属于同一功能版本，因此统一为 `v1.1.0`，不再单独发布 `v1.0.1`。

正式 Release 包含：

- `CodexUsageWidget-v1.1.0-windows.exe`
- `CodexUsageWidget-v1.1.0-windows.exe.sha256`
- `CodexUsageWidget-v1.1.0-windows.zip`
- `CodexUsageWidget-v1.1.0-windows.zip.sha256`
- `CodexUsageWidget-v1.1.0-macos.dmg`
- `CodexUsageWidget-v1.1.0-macos.dmg.sha256`
- GitHub 自动生成的同标签源码包

只有当两个平台的发布门槛全部通过时，才创建并标记正式的 `v1.1.0` Release。未签名的 macOS 构建只能作为受控测试产物，不能混入正式 Release。

## Windows 设计

### 保留现有运行核心

现有 `CodexUsageWidget.ps1`、语言包、测试样本、VBS/CMD 启动器和本机数据格式保持不变。传统 ZIP 继续支持原来的解压后启动方式。

### 单文件 EXE 引导程序

新增一个小型、开源的 C# 引导程序及 PowerShell 构建脚本。构建过程使用 Windows 自带的 .NET Framework 编译能力，不增加第三方依赖。

EXE 内嵌经过发布检查器验证的 Windows 运行包。启动流程为：

1. 获取当前用户的本地应用数据目录。
2. 在 `%LOCALAPPDATA%\CodexUsageWidget\app\v1.1.0` 下准备版本化程序目录。
3. 对内嵌包执行 SHA-256、允许清单和 ZIP 路径安全检查，拒绝绝对路径、父目录跳转、重复路径和意外文件。
4. 先释放到同一父目录下的唯一临时目录；完整验证后再移动为正式版本目录，避免崩溃留下可被误用的半成品。
5. 已存在且版本标记与文件清单均正确时直接复用，不重复写入。
6. 使用隐藏窗口、无终端的方式启动 Windows PowerShell 5.1，并加载释放后的 `CodexUsageWidget.ps1`。
7. 引导程序退出，现有小组件继续负责同一登录会话内的单实例保护。

EXE 只管理 `app` 子目录下的程序文件，不修改现有的 `preferences.json`、`cache-token-ledger.json` 和 `reminders.json`。程序目录损坏时显示本地化错误和修复路径，不静默删除用户文件。

引导程序提供只验证内嵌包和释放结果、不启动界面的自检入口，供构建和下载后回归使用。

## macOS 设计

### 技术选型

macOS 使用 Swift、SwiftUI 与少量 AppKit 原生实现，不依赖 PowerShell 或第三方 UI 框架。部署目标为 macOS 13，正式构建同时包含 `arm64` 和 `x86_64`。

SwiftUI 负责圆环、详情卡、主题与常规视图；AppKit 负责无边框悬浮窗口、屏幕坐标、多显示器吸附、菜单栏项目、鼠标悬停与必要的窗口层级控制。

### 交互一致性

macOS 版保持 Windows 版的核心体验：

- 常规状态只显示百分比圆环；
- 可拖拽，并按当前屏幕可用区域吸附边缘；
- 悬停圆环显示用量详情；
- 活动任务以轻胶囊显示，悬停或键盘聚焦后显示任务数据；
- 提供八套同步主题和五种界面语言；
- 支持键盘打开、关闭详情和辅助功能标签；
- 菜单栏提供显示、语言、主题和退出入口；
- 低用量提醒按同一重置周期去重。

窗口吸附使用 `NSScreen.visibleFrame`，避免覆盖菜单栏和程序坞。界面尺寸允许各语言自然变化，但必须通过实际字体测量和截图检查，不能依赖固定英文宽度。

### 数据发现与持久化

macOS 的 Codex 数据目录按以下顺序解析：

1. 用户此前手动选择并保存的目录；
2. `CODEX_HOME` 环境变量；
3. 当前用户的 `~/.codex`；
4. 前三项均不可用时，由用户手动选择包含 `sessions` 的目录。

取消选择不会触发循环弹窗，后续刷新仍会检查默认位置。

应用自身文件存放在 `~/Library/Application Support/CodexUsageWidget`：

- 界面位置、主题、语言和手动数据路径；
- 累计缓存令牌账本；
- 提醒去重状态。

这些文件与 Windows 版具有相同语义，但不要求两个操作系统之间直接复制或同步。

## 共享行为契约

两个平台不共享运行时代码，只共享能够验证行为一致性的稳定输入和输出契约：

- 五个 JSON 语言包及其键、占位符和长度约束；
- 匿名化会话样本；
- 限制窗口选择、重置周期合并和过期规则；
- 最近 30 分钟活动任务规则；
- 令牌构成、上下文占比和推理占比规则；
- 累计缓存命中与未命中令牌只增加、不重复累计的规则；
- 面向测试的规范化结果快照。

Windows 自检和 macOS 测试必须对同一批样本生成相同的规范化统计结果。平台特有的日期、数字和界面格式化在统计结果之后执行，不进入跨平台数值比较。

## 本地化与错误处理

两个平台继续支持简体中文、繁体中文、英语、日语和韩语。首次启动跟随系统界面语言；用户选择后立即生效并持久化；不支持的语言回退英语。

以下情况必须显示可理解、可操作的本地化状态，而不是退出或闪退：

- 未找到会话目录；
- 选择的目录没有会话；
- 文件无权读取；
- 单条记录损坏或字段无法识别；
- 可选语言包缺失或无效；
- 偏好或累计账本无效；
- Windows 内嵌运行包释放失败；
- macOS 应用无法访问手动选择的目录。

损坏的单条会话记录只影响该记录；可信边界失败不得写入部分偏好或降低累计缓存值。

## 隐私与安全

- 两个平台均不调用 Web API、不做遥测、不要求账号登录，也不上传数据；若用户手动选择网络文件系统，操作系统仍会执行对应文件 I/O。
- 数据读取限定在解析出的 Codex 数据目录；手动目录必须包含预期的 `sessions` 结构。
- Windows EXE 对内嵌 ZIP 执行严格路径与文件清单验证，并使用版本化、先临时后落位的释放流程。
- macOS 直接分发版本启用 Hardened Runtime，使用 Developer ID Application 签名并提交 Apple 公证。
- 证书私钥只允许存在于开发者的 macOS 钥匙串或 GitHub 加密密钥中，不写入仓库、日志、构建产物或聊天内容。
- GitHub Actions 不向来自不受信任分支或外部拉取请求暴露签名密钥。

## 构建与签名

仓库提供可复现的 Windows 和 macOS 构建入口。

Windows 作业：

1. 运行现有自检、发布检查器和启动器回归。
2. 生成经过检查的 Windows ZIP。
3. 编译并嵌入该 ZIP，生成单文件 EXE。
4. 运行 EXE 自检和隐藏启动回归。
5. 生成 ZIP、EXE 及各自 SHA-256。

macOS 作业：

1. 构建单一 `CodexUsageWidget` 应用目标，并运行单元测试与 UI 测试目标。
2. 生成 `arm64` 与 `x86_64` 通用应用。
3. 在没有签名凭据时只产生内部测试产物。
4. 正式发布时使用 Developer ID Application、Hardened Runtime 和安全时间戳签名。
5. 使用 `notarytool` 提交公证，并把票据装订到 DMG。
6. 使用 `codesign`、`spctl` 和 `stapler` 验证最终产物。
7. 生成 DMG 与 SHA-256。

Apple Developer Program 的实名、双重认证、协议和付款必须由账号持有人完成。证书尚未取得不阻止源码和未签名内部构建的开发，但会阻止正式 v1.1.0 macOS 资产及整个同步 Release 的发布。

## 测试与发布门槛

### 共同门槛

- 五种语言的键集、占位符和格式化测试通过。
- 两个平台对共同样本生成相同规范化统计结果。
- 累计缓存账本在重复、降低、乱序和跨任务输入下不下降、不重复累计。
- README、变更记录、隐私说明、安装说明和资产名称与 v1.1.0 一致。
- 发布包不包含真实会话、账号路径、密钥、证书或临时文件。

### Windows 门槛

- 主脚本自检、发布包检查和现有启动器回归通过。
- EXE 自检、首次释放、重复启动和损坏目录错误路径通过。
- 实际启动无可见 CMD 或 PowerShell 窗口，且只留下一个正常响应的小组件实例。
- EXE 与 ZIP 从 GitHub 下载后哈希匹配，并在全新临时目录中通过回归。

### macOS 门槛

- Swift 单元测试和共同样本对比通过。
- Intel 与 Apple 芯片架构均存在于应用二进制中。
- 多显示器拖拽吸附、悬停详情、菜单栏、主题、语言和键盘辅助功能通过实际 macOS 界面回归。
- 五种语言截图无裁切、乱码或空标签。
- `codesign --verify`、`spctl --assess`、公证日志和票据验证全部通过。
- DMG 从 GitHub 下载后哈希匹配，并能在干净环境中安装、首次启动和读取测试会话。

GitHub 托管的 macOS 构建环境负责自动化测试、两种架构构建和单屏界面冒烟；正式发布前还必须在至少一台运行 macOS 13 或更高版本的 Apple 芯片 Mac 上完成实际启动，并用真实双显示器验证跨屏拖拽与边缘吸附。`x86_64` 架构至少通过独立构建环境或 Rosetta 启动验证。真实 macOS 环境尚不可用时，构建只能保持为测试产物或预发布，不能声称完整验收。

## 更新、回滚与清理

Windows EXE 使用版本化程序目录，不覆盖用户数据，也不自动删除旧版本。用户可删除 `%LOCALAPPDATA%\CodexUsageWidget\app` 下不再使用的版本；偏好和累计账本保留在父目录。

macOS 更新通过替换 `/Applications` 中的应用完成，用户数据保留在 Application Support。回滚使用上一版本 Release 资产，不需要迁移统计文件。

自动更新和自动清理旧版本不属于 v1.1.0；只有实际积累造成问题时再单独设计。

## 验收标准

v1.1.0 只有在以下条件同时满足时完成：

1. Windows EXE、Windows ZIP 和 macOS DMG 都来自同一个已推送标签。
2. 启动器源码、Swift 源码、构建脚本、测试和文档均存在于该标签中。
3. Windows 与 macOS 的统计结果通过共同样本一致性检查。
4. 两个平台保持已批准的悬浮圆环和详情交互。
5. macOS DMG 已使用有效 Developer ID 签名并通过 Apple 公证。
6. 所有正式资产、SHA-256 和重新下载回归均通过。
7. GitHub Release 公开可访问，README 与宣传材料指向正确资产。

### Step 0D：选择性扩展决策

接受进入 v1.1.0：

1. **规范化结果契约**：新增版本化快照结构，固定数据来源、观测时间、完整度和数值语义。
2. **真实状态语义**：所有界面区分成功、部分、陈旧、空目录、未发现和无权限，不以零值代替缺失。

### Section 1：架构审查

**结论：OK，接受 3 项补强。** 组件边界保持清楚：Windows 引导程序只负责可信释放与启动；两个运行时各自负责数据和 UI；共同契约只包含稳定输入输出，不成为第三个运行时。

```text
                           fixtures/contract/v1
                   匿名会话 + expected-state.json
                          /                 \
                         v                   v
Windows 发布包 -> C# 引导 -> PowerShell 核心 -> WPF

macOS DMG -------------> 单一 Swift 应用目标
                         | Core/          | UI/
                         +-- 本地解析/状态 +-- SwiftUI/AppKit 圆环/详情/菜单栏

GitHub CI：两端分别对 expected-state.json 验证 -> 候选资产
Release 环境：签名/公证/哈希/重下验证 -> 发布 v1.1.0
```

新增约束：

- 规范化快照必须包含 `schemaVersion`、`sourceKind=local-session-observation`、`observedAt`、`freshness`、`completeness`、限制窗口、任务和累计缓存数值。
- Windows EXE 的内嵌清单拒绝符号链接/重解析点、路径大小写碰撞和超限解压尺寸。
- macOS 菜单栏与圆环共享一个显示状态；隐藏圆环不能停止刷新，退出才停止进程。

状态机：

```text
启动 -> 解析目录 -> [未发现 | 空 | 无权限 | 可读]
可读 -> 刷新中 -> [成功 | 部分 | 陈旧]
成功/部分 -> 定时刷新 -> 刷新中
任何可恢复状态 -> 重新选择目录 -> 解析目录
任何运行状态 -> 退出 -> 已终止

禁止：缺失/失败 -> 伪造 0%；通过 completeness/freshness 枚举阻止。
```

10 倍会话量先受“最近 30 文件 + 有界尾部读取”保护；100 倍时最先增加的是目录枚举成本，不应扩大为全历史扫描。单点故障为上游日志格式、Apple 签名账号和真实 Mac；前者用契约版本阻断陈旧展示，后两者用正式发布门槛阻断。回滚是恢复上一个 Release 资产并保留用户数据，预计数分钟，无数据库迁移。

### Section 2：错误与救援图

| 方法/路径 | 可能失败 | 错误类型 | 处理 | 用户看到 |
|---|---|---|---|---|
| Windows 获取本地应用目录 | 环境目录无效 | `EnvironmentError` | 终止引导，不创建文件 | 本地化“无法确定程序目录” |
| 内嵌包校验 | 哈希、清单、路径、大小不符 | `InvalidDataException` / `CryptographicException` | 不释放、不覆盖旧版本 | 包损坏及重新下载建议 |
| 临时释放/落位 | 无权限、磁盘满、并发 | `UnauthorizedAccessException` / `IOException` | 清理本次临时目录；保留旧版 | 失败阶段与修复路径 |
| 启动 PowerShell | 系统组件缺失或进程失败 | `Win32Exception` | 引导返回非零；不改用户数据 | 启动失败和 ZIP 备用方式 |
| macOS 目录解析 | 候选均不可用 | `DirectoryResolutionError` | 进入未发现状态，提供选择器 | 未找到会话目录 |
| macOS 文件枚举 | 无权限、目录移动 | `CocoaError` | 保留最后快照并标陈旧 | 无法读取及重新选择 |
| 会话解码 | 损坏 JSON、未知字段 | `DecodingError` / `UnsupportedFormatError` | 隔离单条；整体未知则停止刷新 | 部分数据或格式不支持 |
| 偏好读取 | JSON 无效、字段越界 | `PreferenceError` | 使用安全默认值，不覆盖原文件 | 偏好已忽略，可重新设置 |
| 账本更新 | 文件损坏、值下降、写入失败 | `LedgerError` / `IOException` | 不降低内存/磁盘值；原子写失败则保留旧文件 | 累计数据暂未更新 |
| 语言包加载 | 缺包、键/占位符/长度错误 | `LocalizationError` | 可选语言回退英语；英语失败则阻断启动 | 对应语言或双语最小错误 |
| 签名/公证 | 凭据缺失、Apple 拒绝、票据失败 | `SigningGateError` / `NotaryError` | 不创建正式 Release | 仅 CI 维护者看到阻断原因 |
| Release 发布 | 资产缺失、哈希不符、上传中断 | `ReleaseGateError` | 保持草稿；不得发布 | 公开用户仍看到上一版本 |

禁止用无上下文的通用捕获吞掉错误。每个恢复路径必须选择：保留最后可信值并标陈旧、回退安全默认值、或阻断当前发布。

### Section 3：安全与威胁模型

| 威胁 | 可能性 | 影响 | 缓解 |
|---|---|---|---|
| 恶意或损坏内嵌 ZIP 路径穿越 | 低 | 高 | 精确清单、规范化路径、拒绝绝对/父跳转/重复/大小写碰撞/链接、总大小上限、临时后落位。 |
| 手动目录借符号链接越出 `sessions` | 中 | 中 | 解析真实路径；每个候选文件必须仍位于解析后的会话根下，只读打开。 |
| 会话或语言 JSON 造成内存耗尽 | 中 | 中 | 现有尾部读取、文件/行/字符串上限；Swift 使用相同上限。 |
| 路径进入命令行导致注入 | 低 | 高 | 不经过 shell；Windows 使用固定可执行文件和受控 `-File` 参数，macOS 运行时不启动外部命令。 |
| PR 代码窃取 Apple 私钥 | 中 | 高 | PR 工作流无签名密钥；签名只在受保护环境、可信 tag/commit 和人工审批后运行。GitHub 官方也说明 fork PR 不接收 Actions secrets。 |
| 发布包泄露真实路径、会话或证书 | 中 | 高 | 扩展现有发布检查器，扫描完整候选清单并仅放行精确二进制资产。 |
| 伪造陈旧数据误导用户 | 中 | 中 | `observedAt`、`freshness`、`completeness` 为强制字段；未知格式不得显示成成功。 |

运行时不调用 Web API、不做遥测、不上传数据，也不写回 Codex 目录，因此没有远程对象授权面。用户手动选择 UNC 或其他网络文件系统时仍会产生操作系统级文件 I/O，文档不得把它描述成“绝不联网”。Apple 要求 Developer ID、Hardened Runtime 和公证的正式流程保持不变；GitHub 签名 job 不使用 `pull_request_target` 执行外部代码。

### Section 4：数据流与交互边界

```text
会话目录
  | nil -> 未发现 + 选择目录
  | empty -> 空状态，不写累计值
  | unreadable -> 保留最后快照 + 陈旧状态
  v
路径/大小/根目录校验
  | invalid -> 隔离文件或阻断未知整体格式
  v
解析最近事件 -> 规范化状态 -> 单调账本原子写 -> 圆环/详情/提醒
  | 部分损坏       | 冲突/写失败               | 最后更新时间
  +-> completeness=partial                +-> 不伪造成功
```

| 交互 | 边界 | 处理 |
|---|---|---|
| 双击或重复启动 | 两实例竞争 | 现有 Windows mutex；Mac 使用单应用激活策略，第二次只唤醒现有实例。 |
| 刷新重入 | 15 秒定时器撞上慢扫描 | 同一时间只允许一次刷新；下一次 tick 合并，不排队。 |
| 拖到另一屏幕后屏幕断开 | 保存坐标失效 | 按当前屏幕集合夹紧到最近 `visibleFrame`。 |
| 悬停详情时数据刷新 | 内容高度变化 | 保持弹层锚点，原子替换整份视图状态。 |
| 无活动任务 | 空列表 | 隐藏任务容器，保留总体状态，不显示占位胶囊。 |
| 任务在悬停中消失 | 焦点对象失效 | 关闭该任务详情，焦点回到圆环或列表标题。 |
| 目录选择取消 | 循环弹窗风险 | 保持未发现状态，只有用户再次触发才打开选择器。 |
| 睡眠/唤醒或系统时间跳变 | 倒计时错误 | 唤醒后立即刷新；所有重置时间从绝对时间重新计算。 |
| 语言/主题切换中刷新 | 部分 UI 状态 | 先验证资源，再一次性提交偏好并用最后状态重绘。 |
| 减少动态效果 | 光晕/动画不适 | macOS 遵循 Reduce Motion；关闭非必要脉冲，只保留静态状态。 |

### Section 5：代码质量

**结论：OK，拒绝共享运行时抽象。** 最少新结构为：

- Windows：一个 C# 引导源文件、一个构建入口、一个自检入口；不建立通用安装框架。
- macOS：一个原生 Xcode 应用目标 `CodexUsageWidget`，源码仅按 `Core/` 与 `UI/` 文件夹分组；另设一个单元测试目标和一个 UI 测试目标。没有第二个 framework/library 目标，也不为单一实现增加接口工厂或插件系统。
- 共同：`fixtures/contract/v1` 作为唯一跨平台语义源。

固定 bundle identifier 为 `io.github.libaie.codexusagewidget`。业务函数以结果命名，不以 UI 技术命名。任何含五个以上条件分支的 Swift 解析函数拆成现有语义对应的小函数，但不复制一套新的领域层。平台格式化必须在规范化结果之后，避免统计与显示耦合。

### Section 7：性能审查

**结论：OK，无需缓存服务或数据库。**

- 两端每 15 秒最多扫描最近 30 个会话文件；先读 256 KiB 尾部，需要时至多重试 1 MiB。
- 会话解析与文件 I/O 不在 UI 主线程；刷新重入合并为一次。
- 语言包、偏好、账本和内嵌运行包均有大小上限；EXE 解压总量设置固定上限并与精确清单同时校验。
- 自动测试预算：30 个最大夹具的规范化刷新 p95 小于 2 秒；UI 状态提交保持一次性，不逐行刷新视图。
- 10 倍数据量受文件数和尾读上限保护；100 倍首先影响目录枚举，只有测得问题后才考虑索引，v1.1.0 不引入 SQLite。

### Section 10：长期轨迹

可逆性：**4/5**。Windows 引导器可从 Release 移除而不碰主程序；macOS 是独立目录；共同契约是数据文件。唯一持续成本是双解析器跟随上游格式变化，因此 `schemaVersion`、当前/上一真实格式样本和未知格式错误是长期必要控制面。

一年后新维护者应只需回答三个问题：输入格式变了吗、规范化结果变了吗、平台显示是否仍忠实。多供应商、预测、云同步和插件系统都不是该产品当前楔子的延伸，不提前搭平台。

### Section 11：设计与体验

信息层级保持：**百分比圆环 -> 总体详情 -> 活动任务 -> 单任务明细**；菜单栏只是恢复、配置和退出入口，不抢主视图。

| 状态 | 圆环 | 详情卡 | 操作 |
|---|---|---|---|
| 加载 | 中性呼吸或静态占位 | “正在读取本机会话” | 可打开菜单和退出 |
| 未发现 | `—` | 说明未找到目录 | 选择目录 |
| 空 | `—` | 目录有效但暂无会话 | 刷新或更换目录 |
| 错误 | `!` 或中性警示 | 本地化原因 | 重试/重新选择 |
| 部分 | 最近可信百分比 + 小标记 | 列出部分读取和时间 | 查看详情/重试 |
| 陈旧 | 最近可信百分比降饱和 | 明示最后观测时间 | 立即刷新 |
| 成功 | 主题圆环 | 完整用量和任务列表 | 拖拽、悬停、键盘浏览 |

```text
启动 -> 圆环
         | hover / keyboard
         v
       详情卡 -> 任务胶囊 -> 单任务数据
         |                     |
         +---- 移开/关闭 -------+
         |
右键/菜单栏 -> 显示、语言、主题、选择目录、退出
```

最长语言使用真实字体测量；任务胶囊支持键盘焦点；动态摘要作为辅助功能名称；颜色不是唯一状态信号；高对比度与 Reduce Motion 使用系统偏好。没有移动端范围。“像素完全一致”被明确拒绝，但八主题色、圆环层级和详情信息顺序必须一致。

### Pass 1：信息架构（8/10 -> 10/10）

圆环唯一主指标定义为：**当前最紧张且尚未重置的限制窗口的剩余百分比**。

选择算法与现有 Windows 完全一致：

1. 移除 `resetAt <= now` 的窗口。
2. 按 `remainingPercent` 升序选择剩余最少者。
3. 百分比相同时优先 `primary`。
4. 没有未过期窗口时显示等待新观测，不沿用已重置窗口。

示例：主窗口剩余 60%、2 小时后重置；次窗口剩余 30%、1 小时后重置。圆环显示 `30%`。一小时后次窗口过期且尚无新观测时，圆环选择仍有效的主窗口并显示 `60%`；两个窗口都过期时显示 `—`。

```text
常规态：只显示剩余百分比圆环
  -> 悬停 / Enter / 菜单“显示详情”
详情第一层：来源 · 完整度 · 最近观测
详情第二层：剩余百分比 · 当前限制窗口 · 重置时间
详情第三层：令牌构成 · 活动任务胶囊
详情第四层：选中任务明细 · 本机累计缓存
```

约束优先级：用户只看三件事时依次为 **剩余多少、何时重置、这次观测有多新**。活动任务及缓存构成留在后续层级。

### Pass 2：交互状态覆盖（7/10 -> 10/10）

| 表面 | 加载 | 空 | 错误 | 成功 | 部分 | 陈旧 |
|---|---|---|---|---|---|---|
| 圆环 | 无可信快照时显示 `…` | `—` | `!` | 数字 + `%` | 最近有效数字 + 两段缺口外环 | 最近可信数字 + 虚线/降饱和外环 |
| 详情元信息 | “正在读取本机会话” | “目录有效，暂无会话” | 具体原因 | “本机最近观测 · 完整 · 时间” | “本机最近观测 · 部分 · 忽略 N 条” | “上次可信观测 · 时间 · 刷新失败” |
| 主用量 | 占位，不跳成 0 | `—` | `—` | 当前最紧张窗口 | 仅显示本次仍有完整有效窗口的数据 | 保留最后完整快照，不重算 |
| 活动任务 | 保留旧列表并显示刷新中 | 隐藏容器 | 保留旧列表或隐藏 | 最近 30 分钟任务 | 只列完整解码任务 | 保留旧列表并标陈旧 |
| 提醒 | 不触发 | 不触发 | 不触发 | 满足阈值且周期未通知时触发 | 不触发 | 不触发 |
| 目录恢复 | 不出现 | 可更换目录 | 唯一主操作 | 菜单可更换 | 可重试 | 立即刷新/重新选择 |

部分数据规则：

- 若本次存在完整、可验证且未过期的限制事件，可显示该事件，但 `completeness=partial` 且禁止阈值提醒。
- 若本次没有完整限制事件，保留上次完整快照并转为陈旧，不用残缺记录重算百分比。
- 单条损坏显示忽略数量；整体格式未知是错误，不是部分成功。

新鲜度使用两个独立时间：

- `lastSuccessfulScanAt`：成功读完当前目录的时间；超过 45 秒或连续刷新失败时，读状态为陈旧。
- `observedAt`：最新有效限制事件的时间；始终显示。30 分钟内标“最近”，更早标“较早观测”，但只要窗口未重置仍可作为历史观测展示。
- 只有扫描当前、观测不超过 30 分钟、完整度为完整且窗口未重置时，才允许阈值提醒。

每次扫描预算为 10 秒。超过预算：有可信快照则转陈旧，无可信快照则显示可重试错误；下一刷新周期可再次尝试，不积压任务。

- 显示器断开、分辨率或 Dock 位置变化时，在下一帧夹紧窗口，不写入屏幕外坐标。

### 当前实现调用流与根因

```text
启动
  -> Get-WidgetPreferences
       invalid JSON -> 当前静默返回默认值
  -> Restore-WidgetPosition
       -> Complete-WidgetPositionRestore
            -> 当前无条件 Save-WidgetPreferences（可能覆盖损坏原文件）

15 秒 tick
  -> Start-UsageRefresh -> persistent PowerShell runspace
  -> Get-CodexUsageSnapshot
       -> Get-CodexUsageState
            -> 递归枚举/全排序
            -> 完整读取 session_index.jsonl
            -> Read-SessionEvents（坏行静默丢弃）
            -> Update-CumulativeCacheTokens
                 invalid ledger -> 当前空账本 -> 可能写回
  -> Complete-UsageRefresh
       只有 IsCompleted 才结束；当前无 deadline/recovery
```

根因不是某一个 UI 状态，而是三个共享边界没有表达失败信息：持久化加载只有“值”、扫描只有“快照或 null”、worker 只有“完成或未完成”。最小根因修复是让这三个边界各自返回一个小而明确的结果，不在每个调用方补例外分支。

### 冻结的规范化快照契约 v1

规范文件：`fixtures/contract/v1/schema.md`。测试样本使用匿名路径和固定时钟；两端都读同一输入并与人工审过的 `expected-state.json` 比较。

| 规则 | 冻结值 |
|---|---|
| 版本 | 顶层 `schemaVersion` 必须是整数 `1`。未知大版本返回 `unsupported`，不得猜测。 |
| 来源 | `sourceKind` 固定为 `local-session-observation`。 |
| 令牌 | 内部为 signed Int64；JSON 中以十进制字符串输出，避免 `2^53` 以上跨语言歧义。负数、非整数和超出 Int64 均无效。 |
| 加法 | 使用 checked addition；溢出使本次对应字段无效并进入 `partial/error`，绝不环绕或截断。 |
| 百分比 | 使用十进制运算，Midpoint-to-even（银行家舍入）到一位；JSON 为如 `"71.3"` 的字符串或 `null`。UI 再本地化百分号。 |
| 时间 | 所有输入规范化为 UTC；JSON 使用 signed Int64 Unix epoch milliseconds。倒计时只由当前时钟与绝对时间计算。 |
| 边界 | `resetAt <= now` 视为过期；系统时钟回拨或睡眠唤醒后立即从绝对时间重算。 |
| 缺失 | 每个定义字段始终存在；未知数字为 `null`，未知文本为 `null`，集合为 `[]`，不因平台省略键。 |
| 稳定排序 | 限制窗口按 `remainingPercent`、`primary` 优先、`resetAt`、稳定 id；任务按 `observedAt` 降序后 id ordinal；账本按 session id ordinal。 |
| 精度 | UI 可缩写 `1.2 万`，但规范快照和持久化永远保留原始整数，不用显示值回算。 |

最低共同样本必须包含：恰好 `2^53`、`2^53+1`、Int64 最大值、checked overflow、DST 跳变、`resetAt == now`、相同时间戳、主/次窗口并列、乱序事件、单条损坏、全部损坏、未知整体格式、读取失败、缓存值下降与空目录。

预期快照不得由任一平台实现自动覆盖。契约 owner 编写样本，独立 reviewer 审核预期值；Windows/Mac owner 只让实现满足已审快照。


唯一分类表：

| 条件 | 结果 | 展示/提醒 |
|---|---|---|
| 目录有效，无候选记录 | `empty` | `—`；不提醒。 |
| 至少一个完整有效窗口，所有计数为 0 | `complete` | 正常展示；满足新鲜度时可提醒。 |
| 至少一个完整有效窗口，同时有坏行/未知/读取失败 | `partial` | 只显示完整字段和忽略计数；不提醒。 |
| 没有有效窗口，存在未知 schema/event | `unsupported` | `!`；建议更新应用；不沿用为“实时”。 |
| 没有有效窗口，只有损坏或读取失败 | `error` | 有旧可信快照则陈旧显示，否则 `!`；不提醒。 |

| 加载状态 | 内存行为 | 磁盘行为 |
|---|---|---|
| `missing` | 使用默认值 | 第一次真实用户变更时可创建。 |
| `valid` | 使用已验证值 | 只通过现有原子写入更新。 |
| `invalid` | 使用安全内存值并显示恢复入口 | 原字节保持不变；自动刷新、位置恢复、主题/语言初始化均不得写回。只有用户明确“重置本地状态”后才替换。 |

| UI 线程 | 不做目录/文件/JSON I/O；整份不可变 view state 一次提交，自动性能夹具目标小于一帧（16 ms）。 |
| 正常夹具 | 30 个最大尾读文件的本地刷新 p95 < 2 秒；CI 记录耗时但不上传用户数据。 |
| 链接 | Windows 拒绝会话根及后代 reparse point；macOS canonicalize 后要求候选仍在 canonical root 的路径组件边界内。 |
| EXE 载荷 | 精确 allowlist、逐文件 SHA-256、总解压上限、拒绝绝对/父跳转/重复/大小写碰撞/链接；临时目录成功后原子落位。 |

10 秒是用户可见刷新预算，不是假设所有内核 I/O 都可瞬间取消。实现必须在慢/锁定文件和网络路径夹具中证明：超时后 UI 可操作、旧快照仍在、下一周期能用新 worker 成功刷新，且不产生无界 worker 或句柄。

### 并发、生命周期与恢复

| 场景 | 规则 |
|---|---|
| 刷新 tick 重入 | 同一平台同一时刻只有一个 active scan；tick 合并，不排队。 |
| Windows EXE 同时首次启动 | 引导使用版本级命名锁；只有锁 owner 释放/校验，其他实例等待有界时间后复用完整版本。主程序继续使用现有应用 mutex。 |
| EXE 释放中终止 | 只留下本次临时目录；下次清理同版本孤儿临时目录，旧完整版本不变。 |
| 偏好写与退出竞争 | 复用原子写；退出只等待当前小文件写入，不等待新扫描。 |
| Mac 第二次启动 | 由单应用激活现有实例，不创建第二份账本 writer。 |
| 睡眠/唤醒 | 取消陈旧 timer 计算，唤醒后立即刷新并从绝对 UTC 时间重算。 |
| 显示器断开 | 下一主线程帧把圆环和详情夹紧到仍存在的 `visibleFrame`，随后才保存有效位置。 |
| 任务在焦点中消失 | 关闭任务详情，焦点回到圆环或任务列表标题，不指向已释放对象。 |

### Failure Modes Registry（工程增补）

| 路径 | 失败 | 救援 | 必须失败的检查 |
|---|---|---|---|
| 偏好/账本/提醒加载 | JSON 损坏或字段越界 | 内存安全值 + 原文件写保护 + 显式重置 | 自动刷新/位置恢复后原文件逐字节相同。 |
| 会话解析 | 单条坏、全坏、未知 schema | partial / error / unsupported 分开 | 三类输入不得都落到 empty。 |
| 目录枚举 | 10,000 项或超过预算 | partial/stale，不扩大读取 | 大目录在预算后仍可操作且下次恢复。 |
| 文件读取 | 锁定、慢网络卷、权限丢失 | 保留上次可信快照 | worker 可重建，无无界后台任务。 |
| 路径 | junction/symlink 越根 | 拒绝文件，绝不打开 | 越界目标访问计数保持 0。 |
| 数字 | `2^53+1`、Int64 overflow | 字符串保真 / invalid | Windows 与 Swift 输出逐字节一致；overflow 不环绕。 |
| 时间 | DST、回拨、`resetAt==now` | UTC 重算、过期过滤 | 固定时钟两端一致。 |
| 引导 | 两进程、载荷坏、落位中断 | 单 owner、旧完整版本、可重试 | 并发首次 EXE 只产生一个完整 runtime。 |
| 本地化 | 可选包坏 / 英语包坏 | 英语回退 / 内置最小错误 | 错误不依赖待加载语言包。 |
| 通知 | 未授权、重启、过期点击 | 不重复请求/去重/打开当前状态 | 不完整或陈旧状态永不通知。 |
| 签名发布 | secret 缺失、tag 错、上传断 | workflow fail closed、保留草稿 | 任一资产失败都不存在公开 v1.1.0。 |
| 公开后严重问题 | 资产已被下载 | 下线受影响资产，v1.0.0 恢复推荐，发布 v1.1.1 | 原 v1.1.0 tag 永不移动。 |

### 精确发布与回滚顺序

1. 在干净工作树锁定候选 commit SHA 和 `v1.1.0` 功能版本。
2. 从该 SHA 构建无密钥候选，运行共同契约、平台测试、隐私与架构检查。
3. 受保护环境从同一 SHA 重建/签名；Mac 完成 notarize、staple、Gatekeeper；真实 Apple Silicon、Rosetta 和双显示器签核。
4. 所有 gate 通过后才创建不可变 annotated tag `v1.1.0`，并验证 tag peeled target 等于候选 SHA。
5. 从该 tag 创建 GitHub **draft** release，上传 EXE、ZIP、DMG 与校验文件。
6. 从 GitHub 重下全部资产，验证文件名、大小、SHA、Windows 启动、Mac 签名/票据和版本一致。
7. 只有重下验证成功才公开；源码使用同一 tag 的自动 source archives，不另造不同版本源码包。
8. 草稿阶段失败：删除失败候选并从新 commit 重走，不移动既有 tag。若 tag 已建但 release 未公开且代码需改，使用新版本号，不强推/移动 tag。
9. 公开后严重缺陷：下线受影响二进制，把 v1.0.0 恢复为 README 推荐下载，保留 v1.1.0 tag 与审计记录，修复发布 v1.1.1。

选择：**Competitive tier（2–5 分钟）**。不追求 hosted playground；桌面原生 UI 在浏览器里并不真实。一条确定性的本地 demo 命令比新增网站或视频更匹配贡献者。

### Magical Moment Specification

魔法时刻：**贡献者从干净 clone 使用完全虚构的数据，看到与生产结构相同的 55% 圆环和详情卡，并确认没有读取或写入自己的 Codex/小组件状态。**

交付载体：**copy-paste demo command**。

Windows 目标路径：

```powershell
git clone https://github.com/libaie/codex-usage-widget.git
Set-Location .\codex-usage-widget
powershell.exe -NoProfile -ExecutionPolicy Bypass -STA -File .\CodexUsageWidget.ps1 -SelfTest
powershell.exe -NoProfile -ExecutionPolicy Bypass -STA -File .\CodexUsageWidget.ps1 -Demo
```

预期：第三条只输出 `自检通过。`；第四条打开明确标注“演示数据”的 55% 圆环，任务和详情来自 `fixtures/contract/v1/demo`。

macOS 目标路径：

```bash
git clone https://github.com/libaie/codex-usage-widget.git
cd codex-usage-widget
xcodebuild -project macos/CodexUsageWidget.xcodeproj -scheme CodexUsageWidget -destination 'platform=macOS' -derivedDataPath .build test
open .build/Build/Products/Debug/CodexUsageWidget.app --args --demo
```

`-Demo/--demo` 必须：只读已纳入发布检查的匿名 fixture；使用内存偏好/账本/提醒；不读取 `CODEX_HOME`、用户目录或真实状态；不发送通知；使用独立实例标识；详情来源显示“演示数据”。退出后用户状态文件的存在性和字节均不变化。两平台共用同一 demo 规范快照，避免另建演示业务逻辑。

时间目标：已安装平台工具链时，首次确定性 demo ≤5 分钟；完整无密钥检查 Windows ≤10 分钟、macOS/CI ≤15 分钟。冷安装 Xcode 不计入仓库 TTHW，但在前置条件中明确说明。

### Pass 1：Getting Started（4/10 -> 9/10）

当前用户安装已接近一键，但贡献者路径不是：没有 clone-to-demo、Mac 命令、期望输出或匿名可视数据。计划后的理想流程限制为三件事：clone、平台自检、demo。完整 gate 放在下一层，不阻塞第一次成功。
